# Measurements

What a client pays to connect: the exact `tools/list` payload the production tool registry
emits per surface, measured on an in-memory MCP server, and the token count of the model-facing
tool definitions from the vendored tokenizer. No network, no Google, no API key — token counting
is local only: this repository calls no token-count API and holds no model API key anywhere.

- `current.md` — regenerated by `npm run gen` from the working tree; `npm run gen:check` (CI)
  fails when it is stale. Carries neither version nor commit, so it changes only when the emitted
  tool definitions change (a tool edit, an MCP SDK bump that changes the tools/list serialization,
  or a tokenizer bump that changes the counts).
- `<version>-<short sha>/` — an immutable baseline: `tools-list.<surface>.json` (raw payloads) and
  `report.{json,md}` (bytes + tokens). Written once with
  `node scripts/measure-tools.mjs --out docs/measurements/<version>-<sha> --commit <sha>` and pinned
  by hash in `tests/measure.test.ts`; never regenerate one — add a new directory for a new version.
- `Actions → Measure → Run workflow` produces the same report for any ref on a clean runner
  (job summary + artifact); it commits nothing.

## Tokens

`scripts/lib/measure-core.mjs` → `tokenStats()` counts the JSON of the model-facing tool array
(name, description, input_schema), as emitted and with the SDK's `$schema` key stripped, with
`@anthropic-ai/tokenizer` (version recorded in every report). This is a proxy: the API's own
accounting of tool definitions is not observable without a request, and the tokenizer package
predates the current models. Two consequences:

1. **Gate G4 (compact ≥70 % below full) is a ratio on the same tokenizer**, so it holds as long as
   the tokenizer is the same for the "before" and "after" measurement. The absolute "<10K" bound is
   read on the same proxy and stated as such.
2. **Fidelity is validated, not assumed.** On each model-version update (or at intervals at
   the operator's discretion), collect reference counts *outside* this repo — e.g. `usage.input_tokens`
   of a real request that carries a known text, or the Console's token counter — into a JSON file
   `[{ "label", "model", "text", "referenceTokens" }]` (see `tokenizer-fidelity.example.json`) and run

   ```bash
   node scripts/measure-tools.mjs --fidelity <samples.json>
   ```

   It prints local vs reference per sample and exits 1 when any ratio is outside ±10 %
   (`FIDELITY_TOLERANCE`). Record the run (date, tokenizer version, ratio range) in the issue that
   tracks the release. If it drifts, bump or replace the tokenizer and regenerate `current.md`
   (`npm run gen`); baselines stay as they are — comparisons across tokenizer versions use bytes.

Surfaces measured (`SURFACES` in `scripts/lib/measure-core.mjs`): `full`, the
`gmail+calendar+drive+docs+sheets` profile, and the `gmail` / `sheets` groups alone.

Usage evidence for the compact surface comes from the access log:
`wrangler tail --format json > capture.ndjson` for a while, then `npm run tool-usage -- capture.ndjson`
(calls per tool × client; no addresses are printed).
