# CLAUDE.md — Google Workspace MCP (Cloudflare Worker)

Project guide for AI coding agents working in this repo.

## What this is
A remote MCP server on Cloudflare Workers exposing a user's Google Workspace (Sheets, Drive, Docs, Gmail, Calendar, Tasks, Contacts, Chat, Slides, Forms, Photos, YouTube, Meet) as tools, deployed in **two modes from shared code** (same layout as `adamcfield/zoho-analytics-mcp-worker`): the **claude.ai OAuth connector** (`src/oauth.ts`, `wrangler.oauth.jsonc`, primary — `@cloudflare/workers-oauth-provider` with **Google as the upstream identity provider**, one grant per user) and the **bearer-token worker** (`src/index.ts`, `wrangler.jsonc` — `MCP_AUTH_TOKEN` gate, one worker-wide Google account connected via `/google/auth`, podio-style). Transport: Streamable HTTP at `/mcp` (+ legacy SSE at `/sse`) via `McpAgent` from `agents`.

## Layout
- `src/agent.ts` — `GoogleWorkspaceMCP extends McpAgent` shared by both workers: resolves the Google credential (OAuth grant props → else owner grant), builds a `GoogleClient` with the encrypted KV token cache, registers the tools. `VERSION` lives in `src/version.ts` (re-exported here; `google_whoami`/`google_list_tools` return it as `serverVersion`).
- `src/oauth.ts` — claude.ai connector entry: `OAuthProvider` wiring (`/mcp`, `/sse` API handlers; `/authorize`, `/callback`, `/`, `/health` in the default handler).
- `src/index.ts` — bearer worker entry: bearer gate, `/google/auth` owner login routes (from `src/owner.ts`), 503 guards, `/mcp` + `/sse`.
- `src/owner.ts` — bearer worker's owner grant: AES-GCM-encrypted record in `TOKEN_KV` (key derived from `MCP_AUTH_TOKEN` + `GOOGLE_CLIENT_SECRET`) or `GOOGLE_REFRESH_TOKEN`; routes `POST /google/auth/link`, `GET /google/auth?key=`, `GET /callback`, `GET /google/status`, `DELETE /google/auth`.
- `src/auth.ts` — connector consent page, `/authorize` (GET renders + CSRF cookie, POST parks the MCP auth request in KV and redirects to Google with `access_type=offline&prompt=consent`), `/callback` (code exchange → userinfo → `ALLOWED_EMAILS` → `completeAuthorization` with `props: { email, refreshToken, grantedScopes }`); also exports `googleAuthorizeUrl`, `htmlPage`, `revokeGoogleToken` for the bearer worker.
- `src/google/client.ts` — `GoogleClient` (lazy access-token mint + AES-GCM-encrypted KV cache keyed off the refresh token, 401-refresh-retry, 429/5xx backoff, error normalization), `API` base URLs, `exchangeCode`, `fetchUserInfo`.
- `src/google/scopes.ts` — the ONE list of Google scopes (+ required APIs). Consent page, README and tests derive from it. Also `PROFILES` / `expandProfiles` (group-bundle shorthands for `ENABLED_TOOL_GROUPS`/`DISABLED_TOOL_GROUPS`; a **group name always wins over a profile** of the same name, which is what keeps every pre-1.5 value meaning exactly what it did) — `enabledGroups` returns `profiles` alongside `groups`/`unknownGroups`, and `enabledScopes` stays group-driven.
- `src/tools/_shared.ts` — `tool()` definition helper, `registerAll()` (skips `write` tools on `MCP_READONLY`; every callback is `invoke()`), `invoke(def, args, ctx, { via? })` = the one entry point per tool call (single limiter charge, `run()`, access log with optional `via`/`outChars`/`client`), `annotationsFor(def)` (the wire annotations; pinned for every tool in `tests/fixtures/annotations.json`), `ToolCtx.catalog` (`{ manifest, listed, aliases }`, set by `registerTools`), `aliasDefs(canonical)` (the hidden deprecated names built from `RENAMES`) + `mark()`, `run()` → `fail(classifyError(err, scope).message)`, `strip()`/`ok()` compact output, base64/MIME/html helpers. `src/tools/_errors.ts` — the error contract: `ERROR_PREFIX`, `ToolError`/`ToolErrorSchema`, `classifyError` (pure; message = the 1.4.4 tool-error text, golden-pinned in `tests/contracts.test.ts`), `rateLimitError`. `src/tools/listing.ts` — `installListing(server, catalog, { stripSchemaKey? })` owns `tools/list` (byte-equal to the SDK listing). `src/tools/instructions.ts` — `MCP_INSTRUCTIONS` (≤ `MAX_INSTRUCTIONS_CHARS` = 900; re-exported from `index.ts`). `src/tools/naming.ts` — tool-name grammar (`VERB_KINDS`/`VERBS`, `parseToolName`, `kindOf`, `MAX_NAME_LENGTH`, `NAME_EXEMPTIONS`, the 46-entry `RENAMES` old→new table + `ALIAS_ARGS`/`ALIAS_REMOVAL_VERSION`, `aliasesFor`/`canonicalName`). `src/tools/_router.ts` — router zod schemas and discovery-tool input shapes only (engine lands in PR-6).
- `src/tools/surface.ts` — the advertised-vs-registered split: `Surface`, `COMPACT_TOOL_NAMES` (the 16 recipe tools) + `META_ALWAYS`, `toolSurface(env)` (`TOOL_SURFACE`; anything unrecognised falls open to `full` + a health warning), `manifestFor(env)` (= `toolsFor(env)` minus writes under `MCP_READONLY`) and `surfaceFor(env)` / `surfaceAdditions(env)` (`TOOL_SURFACE_ADD`, split into `names` / `filtered` / `unknown` for the health warnings). `META_ALWAYS` is DERIVED from the Meta group, so a meta tool added later is advertised on a compact surface automatically.
- `src/tools/sheets-a1.ts` (pure A1/GridRange/formula-reference helpers: `parseA1`, `gridRangeToA1`, `extractRefs`, `toR1C1`, `compactFormat`), `src/tools/sheets-verify.ts` (`verifyCells` post-write error check, `describeRequests`/`changeTotals`/`attachPreviews` for `sheets_batch_update_spreadsheet` dry runs and summaries), `src/tools/sheets-analysis.ts` (`sheets_audit_spreadsheet`, `sheets_trace_precedents`, `sheets_trace_dependents`). Sheets write tools take `verify` (default true) and re-read the written range; `sheets_batch_update_spreadsheet` takes `dry_run`.
- `src/tools/<group>.ts` — one module per Google product exporting `<group>Tools: ToolDef[]`; `src/tools/_groups.ts` aggregates them (`TOOL_GROUPS`, `ALL_TOOLS`, `toolsFor`) and `src/tools/index.ts` re-exports that plus `registerTools` / `MCP_INSTRUCTIONS`. The catalog lives in `_groups.ts` and not in `index.ts` **so that `surface.ts` can read it without the two importing each other** — keep it a leaf module.
- `src/routing/` — tool selection (which schemas to expose per request), separate from `src/tools/` because nothing here is a tool: `gate.ts` (`readMutationIntent`, `gateTools` — the deterministic mutation gate; no model, ever) and `select.ts` (`selectTools` = prefilter over READ tools → optional binary asks → unconditional union with the gate). **Every write in a selection comes from the gate**; the prefilter cannot volunteer one. `jev.ts` (`createJevAsk` — the optional middle stage, answered by TypeSafe's System One model: one `noul` question per prefiltered READ candidate, batched into one `systemOne` call per request). It takes an INJECTED client through a structural interface and never imports `@typesafe-ai/sdk` — the injection point is `runtime.ts`. Anything unusable — no key, auth, rate limit, timeout, missing/malformed answer, a probability outside [0,1] — THROWS, because `selectTools` turns a throw into the deterministic answer and reports `fallback`. Never guess at a malformed answer: that is the one way this could quietly widen a selection. `runtime.ts` is the ONE place that reads the environment for this path: `jevEnabled` (exactly `"true"`, nothing else), `jevConfigured` (a non-blank `TYPESAFE_API_KEY` exists — never its value) and `jevRuntime(env)`, which dynamically imports the SDK and returns `null` on every failure instead of throwing. `src/tools/select.ts` registers `google_select_tools` (request-bearing, since `tools/list` has no prompt) and `toolsFor` appends it ONLY when the flag is on, so a default deployment's registration and listing are byte-identical — `tests/jev-runtime.test.ts` asserts the listing bytes. The lints read `EVERY_TOOL` (catalog + flag-gated), `ALL_TOOLS` stays the flag-off catalog the README tables and measurements are generated from. Never put `JEV_ENABLED` or `TYPESAFE_API_KEY` in a wrangler config; the key is a Worker secret on the QA worker only (`docs/QA-JEV.md`). Benchmarked by `bench/jev/` (`npm run jev:bench`, gated in CI: mutation recall must be 100%, forbidden selections 0; `npm run jev:live` / the `JEV live benchmark` workflow runs the same 72 cases against the model with the key from a repository secret).
- `src/privacy.ts` — plain-text privacy policy served at `/privacy` by both workers (Google consent-screen branding needs a homepage = `/` and a privacy URL). `src/health.ts` — shared `/health` body (`groups`, `allowList`, `warnings` — the alerting field).
- Production guards: `ALLOWED_EMAILS` fails closed (`ALLOW_ANY_GOOGLE_ACCOUNT="true"` opts out); `ENABLED_TOOL_GROUPS`/`DISABLED_TOOL_GROUPS` → `toolsFor(env)` + `enabledScopes(env)` (scopes.ts) drive the tool list, consent page, authorize URL and missing-scope checks — keep every scope consumer on those helpers, never on `SCOPE_LIST`; `RateLimiter` per session, charged once per call in `invoke()` (`TOOL_RATE_LIMIT_PER_MIN`); `AUTH_RATE_LIMIT` ratelimits binding fronts the connector's auth endpoints; `secure()` adds the security headers to every non-MCP response; GoogleClient fetches carry `AbortSignal.timeout` (`timeoutMs`, uploads 120s). `docs/OPERATIONS.md` is the runbook; bump `VERSION` + `package.json` + `package-lock.json` (`npm version <v> --no-git-tag-version --allow-same-version`) + `CHANGELOG.md` together (a test enforces the mirror on all three); `docs/measurements/current.md` carries no version, so a bump alone does not need `npm run gen`.
- `tests/` — vitest (no network; `fetch` is injected/mocked; worker entry tests stub `agents/mcp` with `vi.mock` and `cloudflare:workers` via the alias + `server.deps.inline` in `vitest.config.ts` → `tests/stubs/cloudflare-workers.ts`). `scripts/` — `setup.sh` (deploy both), `smoke.mjs` (mode-aware post-deploy checks + `--e2e`), `login.mjs` (get a connector token without Claude), `gen-tools-md.mjs` (README tool/scope/rename tables + `bench/tool-aliases.json`), `measure-tools.mjs` + `lib/measure-core.mjs` (tools/list bytes + local-tokenizer tokens per surface; `--fidelity` checks the tokenizer against reference counts), `tool-usage.mjs` (access-log → calls per tool × client), `lib/mcp-http.mjs` (bearer MCP client over Streamable HTTP for scripts). `bench/` = the A/B/C orientation benchmark (`tasks.json` T01–T21, `fixtures.mjs` sandbox builder, `score.mjs` gates G1–G8; harness `scripts/bench-run.mjs` + `scripts/lib/bench/*` — execution policy, graders, drivers; see `bench/README.md`). `tests/helpers/mcp.ts` = shared in-memory client↔server pair. `tests/contracts.test.ts` pins the PR-3 contracts (golden error text, annotations fixture, tools/list byte-equality, invoke/catalog/client); `tests/budget.test.ts` holds the model-facing byte ceilings per surface (`BUDGET` — raise only with a measurement in the PR); `tests/hygiene.test.ts` is the PR-4 naming lint (grammar, verb-kind vs flags, cross-references, the rename table, aliases on the wire).

## Conventions when adding/editing tools
- `tool({ name, description, scope, input, write?, destructive?, idempotent?, handler })` from `_shared.ts`; name = `<group>_<verb>_<noun>` with the verb from `VERB_KINDS` (naming.ts) and a non-empty noun; every tool sets `scope` to the Google scope URL it needs. A write tool declares the flags its verb promises (`tests/hygiene.test.ts` checks them against `VERB_KINDS`) — additive verbs `destructive: false`, `*_idempotent` verbs `idempotent: true`.
- Renaming a tool: add the old→new pair to `RENAMES` (never just rename the def), run `npm run gen`, and fix every description/hint that names it — the xref lint fails on a name that no longer exists.
- Handlers return plain data (the framework compacts + stringifies) and **throw** on bad input; never return `{ isError }` yourself.
- Reads: no `write`. Anything that mutates: `write: true`. Irreversible (delete, send, end conference): `destructive: true`. Sending mail requires `confirm: Confirm` (`z.literal(true)`).
- Compact outputs: pick fields, use `listResult(items, nextPageToken)`; never dump raw Google objects unless the tool is explicitly a raw escape hatch (`*_batch_update`, `google_api_request`).
- IDs go through `enc()` when they are a single path segment; resource names containing `/` (`spaces/x/messages/y`, `people/c1`) are appended as-is.
- New scope → add to `scopes.ts` (+ API to `REQUIRED_APIS`), README table regenerates from it; users must reconnect to pick up new scopes.
- zod v4 only (`z.enum`, `.default`, `.describe`); no `.email()` etc. `tests/tools.test.ts` converts every input schema to JSON Schema — keep it passing.

## Workflows
- `npm run typecheck` · `npm test` · `npm run dev` / `npm run dev:oauth` (need `.dev.vars`, see `.dev.vars.example`) · `npm run deploy` (bearer) · `npm run deploy:oauth` (connector) · `npm run smoke -- <origin>`.
- Both workers export the same Durable Object class name (`GoogleWorkspaceMCP`) with their own `MCP_OBJECT` binding + migration; keep the migrations in both wrangler configs in sync.
- Regenerate generated files after tool changes: `npm run gen` (README tables via `scripts/gen-tools-md.mjs` + `docs/measurements/current.md` via `scripts/measure-tools.mjs`); CI runs `npm run gen:check`. Baseline directories under `docs/measurements/<version>-<sha>/` are immutable (hash-pinned in `tests/measure.test.ts`) — never regenerate one, add a new one. Token counts are LOCAL ONLY (`@anthropic-ai/tokenizer`): never call a token-count API and never add a model API key anywhere (scripts, workflows, secrets). Tokenizer fidelity is validated against externally obtained reference counts with `node scripts/measure-tools.mjs --fidelity <samples.json>` per model-version update (docs/measurements/README.md). `src/` typechecks against Workers types only; `tests/tsconfig.json` adds Node types (`npm run typecheck` runs both). Benchmark rules: fixtures and transcripts are namespaced `[MCP-BENCH]` and live only in `bench/fixtures.local.json` / `bench/runs/` (gitignored); the harness executes a tool only if the task allow-list ∪ read-only set permits it and the hard-deny list does not (`scripts/lib/bench/policy.mjs`); `bench.yml` never runs a model or touches Google; no harness driver runs a model at all (`replay` and `transcripts` only — zero model API use). That rule is about the A/B/C orientation benchmark in `bench/` and about token counting, which stays on the local tokenizer with no API key anywhere. It is NOT a rule against the tool-selection benchmark in `bench/jev/` calling TypeSafe: that is the feature under test, it runs only behind `--live` from `jev-live.yml` with `TYPESAFE_API_KEY` from a repository secret, and the CI gate on every push is still the offline deterministic run.
- Always run `npm run typecheck` and `npm test` before committing. CI runs both + a `wrangler deploy --dry-run` bundle.

## Gotchas learned
- Workers: bind global fetch (`fetch.bind(globalThis)`) before storing it — bare `this.fetch(...)` throws "Illegal invocation".
- The Durable Object binding must be `MCP_OBJECT` and the class listed in a `new_sqlite_classes` migration; `nodejs_compat` is required by the MCP SDK.
- `McpAgent.serve()` is Streamable HTTP; legacy SSE is `serveSSE()` — don't route `/sse` to `serve`.
- Google `prompt=consent` is required to get a refresh token on repeat sign-ins; refresh tokens from an OAuth app in *Testing* status die after 7 days (publish it or use an Internal Workspace app).
- Google removed the broad Photos Library scopes on 2025-03-31 — never add `photoslibrary` / `photoslibrary.readonly` back; the consent flow would fail with `invalid_scope`.
- People `searchContacts` needs a warm-up call with an empty query first, otherwise the first real search returns nothing.
- Tasks: anything completed in Google's own apps is `hidden` immediately — `showCompleted` needs `showHidden` too (the tool sets both).
- Forms: `forms.create` publishes by default; `unpublished=true` on create makes a draft. Meet: `spaces.patch`/`:endActiveConference` need the server space id (meeting codes are resolved via `spaces.get` first); `conferenceRecords.list` filters on `space.meeting_code` for codes and `space.name` for ids.
- Drive files have exactly one parent (no multi-parent since 2020) — moves always replace the parent; per-tab CSV goes through the Sheets API, not the docs.google.com export URL.
- `/authorize` POST is bound to the GET via the `gws_csrf` cookie + hidden field; tests must send both.
- `strip()` keeps `null` inside arrays on purpose (Sheets rows are positional) but DROPS empty arrays/objects everywhere — never encode a meaningful "empty" as `[]`/`{}` (a free calendar's `busy: []` vanished and read as "calendar missing"; `missingScopes: []` disappeared). Use a count or boolean (`busyCount: 0`, `allScopesGranted: true`) next to the list.
- `google_api_request` requires `confirm=true` for POST/PUT/PATCH/DELETE (QA found it bypassed every dedicated-tool gate); keep it that way. Sheets locale for Hebrew is the legacy `iw_IL` (`he_IL` → 400); `sheets_create_spreadsheet` maps it. `freeBusy.query` returns per-calendar `errors` for unreadable ids — `calendar_get_free_busy` lists those under `unavailable` with `ok=false` and emits every readable calendar with `busyCount`. `events.move` echoes the cancelled source stub; re-read from the destination. Forms: `documentTitle` does NOT default to `title` on Google's side. Gmail bodies are capped by `max_chars` (`totalChars`/`returnedChars`/`truncated`, same names as Docs/Drive); `format=full` is structure-only and keeps headers by ALLOW-list (`KEPT_HEADER`; `headersOmitted` counts the rest). `htmlToText` decodes named entities from a curated table (`NAMED_ENTITIES`), drops hrefs over 200 chars (tracking links) and renders image-only anchors as `alt (url)` / `[link] `. Drive omits `size` on `application/vnd.google-apps.*` (placeholder "1024").
- Content-bearing reads spread `provenance(source, fields)` FIRST in their result (the notice must precede the content in the serialized JSON). Apply it by content, not by format name: every Gmail format (text/html/full/raw), search/draft snippets, attachment text, Sheets values, Slides text all carry it. claude.ai caches tool schemas per connector — new parameters are invisible to existing connections until re-added; server-side defaults still apply.
- Retry policy in `GoogleClient.request`: POSTs are NOT retried after a timeout/5xx (duplicate sends); pass `idempotent: true` on read-only POSTs (searches, freeBusy). All KV keys this code writes are prefixed `gws:` (the namespace may be shared with sibling workers). `photos_download_media_item` sends the bearer only to `lh*.googleusercontent.com` / `photospicker.googleapis.com` with `redirect: "manual"`. Multipart uploads go through `multipartRelated()`; Drive query escaping and folder moves through `src/tools/_drive.ts`.
- Google returns `replies: [{}]` for most batchUpdate request types — the change summary comes from `describeRequests`, not from the reply. Circular references surface as `#REF!` with a "Circular dependency detected" message (that text is the only signal).
- vitest needs the `.js`→`.ts` alias in `vitest.config.ts` because source uses NodeNext-style `.js` import specifiers. `npm install` with npm 10.9 needed `--legacy-peer-deps` once (npm arborist bug with vitest's peer set); `npm ci` from the lockfile is fine.
- Every pre-1.5 tool name is a **hidden alias**: `aliasDefs(toolsFor(env))` builds one alias per `RENAMES` entry whose target is enabled and registers it next to that target, so it is callable but never in `tools/list` (zero bytes) — claude.ai connections cached on the old names keep working. An alias carries the target's schema, scope and gates — a `confirm` gate, `MCP_READONLY` or a scope check can never be bypassed by calling the old name — logs the name the caller used, and appends `deprecated: {alias, use}` to an object result. They live in `ctx.catalog.aliases` (never in `catalog.manifest`/`listed`) and are removed in 2.0 (`ALIAS_REMOVAL_VERSION`).
- Manifest ≠ surface: `manifestFor(env)` is what gets **registered** (and what aliases are built from), `surfaceFor(env)` is only what `tools/list` **advertises**. Hiding a tool never unregisters it — a hidden tool, and a hidden alias of one, stays callable by name, which is what keeps a cached claude.ai connector working. A compact surface is always a subset of the manifest, so a disabled group, a missing scope or `MCP_READONLY` still wins; and scopes are group-driven, so the surface never changes what is requested at consent. `TOOL_SURFACE` unset/blank/mistyped = `full` = today's listing, byte for byte; the value is matched EXACTLY (`"compact"`, not `"COMPACT"`), like `MCP_READONLY`'s `"true"`. One deliberate non-parity: `registerTools` now honours `env.MCP_READONLY` on its own, where PR-4 relied only on `ctx.readOnly` — and `/health.tools` is the manifest, so it drops on a read-only deployment.
- `installListing` must run AFTER `registerAll` — the SDK installs its own `tools/list` handler lazily on the first `registerTool`, and `server.server.setRequestHandler` replaces it; never touch SDK private fields (`_registeredTools`, `_requestHandlers`). SDK 1.30.0 stamps `execution: { taskSupport: "forbidden" }` on every listed tool, so `toWireTool` emits it too (key order name, description, inputSchema, annotations, execution). Scripts that bundle `src/tools/index.ts` with esbuild must emit under `node_modules/.cache` (not `os.tmpdir()`), because `listing.ts` imports the SDK at runtime.
- Public repository: `tests/public-hygiene.test.ts` fails on tracker/decision codes, named mailboxes at mail providers, live `workers.dev` hosts, filled-in Wrangler configs, and any word on its SHA-256 deny-list (private organisation names, stored as digests so the lint does not publish them). Invented test data uses `example.com`, never a real company domain.
